# 「UI 비정상 종료 감지」 텔레그램이 안 나가는 것 고치기

생성: 2026-11-25 13:35

## 무엇이 문제인가

2026-11-25 10:26 크래시 시험(main.py 두 프로세스를 PID로 강제 종료)에서 run_loop.ps1이 19초 뒤 다시 켰고 기동 알림은 왔다.
그런데 Watchdog이 보내야 할 「UI 비정상 종료 감지 (PID=…)」 알림은 휴대폰에 오지 않았다(사용자 스크린샷으로 확인).

## 증거

- `logs/20261125_watchdog.txt`: 10:26:07 `UI 프로세스(PID=23916) 사라짐 → Watchdog 종료` 다음에 `[SYSTEM] 텔레그램 발송 완료` 줄이 없다. 기동 알림(10:24:58, 10:26:24)은 「발송 완료」가 찍힘.
- 코드: `processes/watchdog_process.py:500`부터 `503`까지 — `tg(...)` 직후 `_kill_detection` 뒤 `break`로 Watchdog이 끝난다.

## 추정(확인 필요)

`tg()`가 발송을 다른 스레드(데몬)로 넘기고 바로 돌아오는데, 그 직후 Watchdog 프로세스가 끝나 발송 도중 죽는다.
먼저 `tg` 정의를 읽어 비동기인지 확인한다. 맞으면 종료 전에 그 발송만 동기로 보내거나 짧게 기다린다(같은 길을 쓰는 다른 「종료 직전 알림」도 같이 본다).

## 확인 방법

시험으로 가짜 텔레그램 서버를 세워 「부모 사라짐 → 종료」 경로에서 요청이 도착하는지 본다. 실조건은 감시PC에서 main.py PID 강제 종료 뒤 휴대폰에 두 통(비정상 종료 + 기동)이 오는지.
계획 문서 `docs/plan/done/20261125-0953-스스로-켜지고-크래시-뒤-다시-켜기.md` 「사람 확인」 M1 줄도 그때 채운다. M5(재부팅 뒤 스스로 켜짐)는 수요일 03:59 예약 재부팅 뒤 확인.
