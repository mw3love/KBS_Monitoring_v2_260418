# 로그창 펄스 애니메이션이 지워진 항목을 건드려 RuntimeError

생성: 2026-10-27 12:28

## 증상 (실측)

`logs/20261027_ui.txt` 08:57:08에 `UNHANDLED EXCEPTION (sys.excepthook)` 2건:

```
File "ui/log_widget.py", line 668, in <lambda>
    lambda s=step, it=item: self._pulse_step(it, s, total_steps)
File "ui/log_widget.py", line 672, in _pulse_step
    data: LogItemData = item.data(Qt.UserRole)
RuntimeError: Internal C++ object (PySide6.QtWidgets.QListWidgetItem) already deleted.
```

상황: 캡처카드 USB를 재연결해 8채널 블랙 감지 로그와 오디오 실패 로그가 한꺼번에 몰린 순간. 프로그램은 계속 돌았다(excepthook이 잡음). 10/20~10/26 UI 로그에는 0건이라 드문 경합이다.

## 원인 추정 (코드만 봄, 재현 안 함)

`_trigger_pulse()`(`ui/log_widget.py:661`)가 새 항목마다 `QTimer.singleShot`을 200ms 간격으로 7번(최대 1.4초) 예약하고, 람다가 `QListWidgetItem`을 붙잡고 있다. 그 1.4초 안에 그 항목이 지워지면 C++ 객체만 사라지고, 나중에 타이머가 `item.data()`를 호출하다 RuntimeError가 난다. 항목이 지워지는 경로는 로그 500개 상한 트림, "Log 초기화", 필터 재구성 등이다. 실제로 어느 경로였는지는 확인 필요.

## 할 일

1. 항목이 지워지는 경로를 찾아(`takeItem`/`clear`/500개 트림) 위 추정이 맞는지 확인한다.
2. 수정 후보 (추천 순서):
   - `_pulse_step` 맨 앞에서 `shiboken6.isValid(item)`으로 확인하거나 `RuntimeError`를 잡아 조용히 return. 가장 작은 변경이다.
   - 항목별 타이머 7개 대신 위젯 하나에 펄스 타이머를 두고, 살아 있는 항목만 순회하는 방식. 변경이 더 크다.
3. 끝의 기준: 오프스크린으로 띄운 LogWidget에 로그를 600개 넘게 빠르게 넣고 곧바로 "Log 초기화"를 하는 시험에서 excepthook 오류가 0건.

## 주의
