## 배경

- 2026-11-19 미디어창의기술전 발표에서 KBS 쪽은 10분, 본편 10장 + 부록 3장. 청중은 방송기술 엔지니어로, 컴퓨터 전공은 아니다.
- 사용자는 PPT(Slides 아티팩트 https://claude.ai/artifact/YHKrFEC7JcrQqstRccQrY4)보다 **해설 구성**을 훨씬 좋아한다. 짧은 제목(예: 「표지 — v1에서 v2로」), 빨간 세로줄 한 줄 요지, 「이 장이 말하는 것」, 낱말 풀이, 비유, 예상 질문 구성이 마음에 든다고 했다. 그래서 **해설 HTML로 발표하기로** 했다.
- 지금 만든 것은 `docs/발표준비/KBS_발표용_해설.html`(오프라인용, 더블클릭으로 열림)과 같은 내용의 아티팩트 https://claude.ai/artifact/GVXaFr2pk5tS1XWpitx6zr(예비용)이다.
  - 장 하나가 한 섹션이고, 섹션이 화면보다 길어서 스크롤이 필요하다.
  - →/← 키로 장을 넘긴다.
  - 화면은 밝은 테마로 고정했다.
  - 내부 메모(쉽게 만든다면·난이도·「추정」 문장)는 이미 뺐다.
  - 낱말 풀이는 용어 고르기(https://claude.ai/artifact/5o53s7Q2CvfVvrBm46FQ7G, db `picks/main`, 추천값 그대로)에서 「설명」으로 고른 29개만 남겼다.
- 해설 공부용 원본은 `docs/발표준비/KBS_슬라이드_해설.src.html`이다. 그림 자리는 `{{IMG:…}}`로 되어 있고, 공부용 아티팩트는 https://claude.ai/artifact/Y9vrEzBrdNKCBidneEezk4 이다.
- 발표용 HTML을 만든 변환 스크립트는 지난 세션 scratchpad에 있어서 사라졌을 수 있다. 다만 규칙은 위 내용이 전부라, 지금 `KBS_발표용_해설.html`을 출발점으로 삼으면 된다.

## 할 일 (사용자 결정, 2026-11-18)

1. **1920×1080 고정 캔버스로 만든다.** 쪽마다 1920×1080 상자를 두고, 창 크기에 맞춰 비율을 유지한 채 키우거나 줄인다(위아래나 좌우에 여백이 생기는 레터박스). 그러면 발표 PC·프로젝터가 달라도 배치가 같다. 스크롤은 없앤다.
2. **장마다 2~3쪽으로 차례로 나눈다. →로만 넘긴다.** 사용자는 「본 쪽+보조 쪽(↓)」 추천 대신 이 방식을 골랐다.
   - 한 장의 쪽 구성 예: ① 요지 + 「이 장이 말하는 것」 + 그림 → ② 이어지는 설명·낱말 풀이·비유 → ③ 「이런 게 궁금하실 텐데요」.
   - 글이 짧은 장(결과·부록)은 1쪽으로 한다.
   - 쪽 머리에 장 제목과 「2/3」 같은 장 안 쪽 번호를 둔다. 오른쪽 아래에는 전체 쪽 번호를 둔다.
3. 해설 글은 줄이지 말고 쪽으로 나누는 게 기본이다. 다만 쪽 하나에서 글자가 너무 작아지면(본문 26px 미만) 쪽을 하나 더 만든다.
4. 확인: Edge 헤드리스로 1920×1080 캡처(`--window-size=1920,1080 --screenshot`)를 떠서 넘치는 쪽이 0인지 본다. 키보드 넘김은 사용자가 확인한다.
5. 끝나면 `docs/발표준비/KBS_발표용_해설.html`을 덮어쓰고 아티팩트 GVXaFr2…도 갱신한다. 그다음 커밋·push를 묻는다. 버전 번호는 그대로 둔다.
