# 종합점검 수정분(2026-10-03) 감시PC 배포 + 실조건 관찰

생성: 2026-10-03 17:13

## 배경
2026-10-03 개발 PC에서 종합점검을 하고 수정했다. 상세는 `docs/261003_프로그램_종합점검.md`에 있다.
대상 커밋은 `835382c`~`377a5a7`(8개)다. 검증은 모두 개발 PC + 시험 영상(프록시검증)이라 **감시PC 실조건 확인이 남았다**.

핵심 수정:
- F10: Detection이 강제 종료되면 UI가 영구 정지하던 문제(`cmd_event`/`state_lock` 제거). 재spawn 직후 UI가 멈추던 원인이었다.
- F1: 감지 메인 루프가 20초 동안 멈추면 heartbeat가 멈추고 Watchdog이 재spawn한다. 정지 시 `logs/fault_detection.log`에 스택이 남는다.
- F4: 기동 직후 반복해서 죽으면 재spawn 간격을 5→300초까지 늘리고, 4회째부터 개별 텔레그램을 생략한다.
- F2: 설정 "알림음 지속(초)"가 실제로 적용된다. F5: 설정 숫자 칸 입력 검사. F9: StreamError를 UI 로그 파일에도 기록한다.
- P1: UI 멈춤 감시(`data/ui_heartbeat.dat`, 30초). P2: 기동 텔레그램에 자가점검 줄 추가.
- 안 쓰는 코드 정리(IPC 메시지 5종 등).

## 할 일 (감시PC)
1. `git pull`을 한다. **`실행.bat`을 돌리는 cmd.exe 창까지 통째로 껐다 켠다.** CLAUDE.md "실행.bat 책갈피 어긋남" 함정 때문인데, 이번엔 `실행.bat`을 바꾸지 않았지만 안전하게 하는 것이다.
2. 기동 텔레그램 둘째 줄의 `기동 점검:`이 모두 ✓인지 확인한다(Python 3.13.x, 감지영역 V/A 수가 0이 아님, ffmpeg, 디스크). ✗가 있으면 그 항목부터 처리한다.
3. 며칠 운영하면서 다음을 확인한다.
   - 잘못된 `감지 메인 루프 응답 없음` / `heartbeat stale` 재spawn이 없는지(`logs/*_detection.txt`, `*_watchdog.txt`).
   - 잘못된 `UI 응답 없음` 알림이 없는지. 특히 PC 절전 복귀 직후 1회 오탐 가능성은 미검증이다.
     - 2026-10-03 "UI 응답 없음 (1791025124초)" → 1초 뒤 "회복" 반복 오탐은 빈 파일 읽기 때문이었고 `3e74ac0`에서 고쳤다. 이 커밋을 반영해 재기동한 뒤에도 같은 알림이 나면 다른 원인이다.
   - 실제 알람이 났을 때 알림음이 설정한 초가 지나면 멈추고, 깜빡임은 유지되는지(F2 실조건).
4. 이전 운영 로그에서 `재spawn 완료` 줄을 찾아본다. 있었다면 그 시각에 UI가 멈췄는지(F10이 과거에 실제로 발생했는지) 확인해 보고서에 적는다.

## 판단 기준
- 며칠 동안 오탐 0건이고 점검표가 모두 ✓이면 완료로 처리하고, `docs/261003_프로그램_종합점검.md`에 "실조건검증" 결과를 추가한다.
- 오탐이 나면 `LOOP_STALE_SEC`(20초, `processes/detection_process.py`)와 `_UI_STALE_SEC`(30초, `processes/watchdog_process.py`)를 먼저 의심한다. 그때 로그와 `fault_detection.log`의 스택으로 원인을 본다.
