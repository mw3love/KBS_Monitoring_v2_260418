[약 1분 10초] - v1 문제의 답: 한 덩어리를 셋으로. 소유권 원칙 — main(UI)이 공유메모리·큐를 만들고 소유, Watchdog이 Detection을 띄우고 소유. - 표가 핵심: 각 장애를 누가 무엇으로 몇 초 안에 알아채는지. - Detection: 별도 writer 스레드가 5초마다 heartbeat 파일을 갱신. 단, 메인 루프가 20초 넘게 touch 안 하면 갱신을 멈춤 → '프로세스는 살아 있는데 루프만 멈춘' 경우도 잡힘. Watchdog은 10초 무변화면 kill·재spawn. 새 Detection은 설정 파일을 스스로 읽고 뜨고, DetectionReady를 보내면 UI가 감지 ON/음량/정파 상태/ROI를 다시 넣어 줌. - 반복 크래시는 지수 백오프(5→10→20초…최대 5분)로 알림 폭주 방지. - UI: 2초마다 시각을 파일에 쓰고, 30초 묵으면 Watchdog이 통보. 힙손상처럼 '살아 있는데 고장'인 경우 UI는 파일 하나만 쓰고 통보는 Watchdog이 대신(다음 다음 장). - 큐는 put_nowait + 가득 차면 하나 버리고 넣기 → 어떤 경우에도 판정 루프가 블로킹되지 않음.
