화면 프로그램 메모리 손상 6회 → 85일 재발 0회

4~5일마다 화면 프로그램만 조용히 고장 났다. 관측 → 우회 → 제거 실험으로 「Python 3.14 환경」을 지목했고, 3.13으로 고정한 뒤 재발이 없다.

증상 — 오래 켜 두면 화면 프로그램의 메모리(힙)가 손상돼 새 객체를 하나도 못 만듦. 창은 멀쩡해 보이는데 설정창 · 경보음 · 조작이 먹통. 재현 불가.

제거 실험 = 장비를 하나씩 바이패스해 보기

Q. 그럼 Python 3.14의 버그인가요?

모릅니다. 「3.14 환경에서만 재발」까지 실험으로 좁혔고, 85일 무재발은 예전 고장 주기의 17배가 넘습니다.

[약 1분] - 가장 오래 쫓은 버그. 4~5일마다 화면 프로그램만 조용히 고장: 새 객체를 못 만듦. 창은 멀쩡해 보여서 더 위험. - 재현이 안 되니 관측부터. 4차에서 큰 발견: 고장 난 화면은 텔레그램조차 못 보낸다. 되는 건 파일 쓰기뿐 → 화면은 파일만 남기고 Watchdog이 대신 알림. 42시간 방치되던 게 10분 안 통보로. - 그다음 제거 실험: 장비를 하나씩 바이패스하듯 용의자를 하나씩 끄고, 그래도 재발하면 무죄. Round 1 셋 다 무죄, Round 2 파이썬 3.14→3.13에서 무사고. - 6차는 의도치 않은 대조군: 재배포 때 3.13 환경이 빠져 3.14로 돌아가자 재발. 이후 85일 0회 — 예전 주기의 17배 넘게. - 정직하게: 왜 그런지는 모른다. 실험으로 범위를 좁혀 그 환경을 뺐다. 감시 프로그램은 별도라 그동안에도 감시는 계속됐다(앞 장의 분리 효과).
