## 2. 원하는 동작

**켜기와 다시 켜기**

1. 사용자가 `실행.bat`을 더블클릭하거나 로그인 때 바로가기가 실행한다. `실행.bat`은 지금처럼 venv 확인·설치·PYEXE 고르기를 한 뒤, 괄호 블록 하나 안에서 다음을 차례로 한다: `powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0run_loop.ps1" -Python "%PYEXE%"` → 그 종료 코드가 0이 아니면(스크립트가 없거나 실행 정책에 막힘) 콘솔과 `logs\stderr_debug.txt`에 NOTICE를 남기고 지금처럼 main.py를 한 번 직접 켠다 → `exit /b`. cmd는 괄호 블록을 통째로 읽은 뒤 실행하므로, 도는 중에 `실행.bat`을 고쳐도 이 cmd.exe는 엉뚱한 줄을 읽지 않는다. `실행.bat`은 ASCII 전용을 지킨다.
2. `run_loop.ps1`은 인자로 `-Python`(필수), `-Main`(기본 저장소의 `main.py`), `-LogDir`(기본 저장소의 `logs`), `-StderrPath`(기본 `-LogDir` 안의 `stderr_debug.txt`), `-BaseDelaySec 15`, `-MaxDelaySec 300`, `-StableSec 120`, `-ChildWaitSec 30`, `-RestartDelaySec 2`, `-SnapshotSec 5`를 받는다. 시험은 이 인자로 진짜 `logs/`와 긴 대기를 피한다.
3. 반복 한 바퀴: main.py를 stderr를 `-StderrPath`에 덧붙이도록 켠다(예: `cmd.exe /c` 안에서 `2>>`). 켠 시각과 PID를 기록 파일에 적는다. 끝날 때까지 `-SnapshotSec`마다 그 프로세스의 자손 PID(ParentProcessId를 따라 내려감)와 각 프로세스의 생성 시각을 모아 둔다. 목록은 그 실행 동안 덮어쓰지 않고 쌓는다(Watchdog이 Detection을 다시 띄우면 새 PID가 더해짐). 이미 죽은 것은 5의 확인에서 걸러진다. venv의 `python.exe`는 진짜 파이썬을 자식으로 띄우는 대리 실행 파일이라, 자손에는 진짜 main.py·Watchdog·Detection이 모두 들어간다. 종료 코드를 확실히 받는다. `Start-Process -PassThru`는 핸들을 먼저 읽지 않으면 `ExitCode`가 비는 함정이 있으니, 쓰려면 시험으로 확인한다.
4. 끝나면 종료 코드로 가른다:
   - 0: 「사람이 닫음(코드 0) — 멈춤」을 적고 스크립트가 0으로 끝난다. 콘솔 창도 닫힌다.
   - 42: 「예약 재시작(코드 42)」을 적고 아래 5의 자손 기다리기 뒤 `-RestartDelaySec` 뒤에 다시 켠다. 크래시 간격은 바꾸지 않는다.
   - 그 밖: 「크래시(코드 N, M초 돌았음) — K초 뒤 다시 켬」을 적는다. K는 0칸 「연속 크래시 간격」대로 정한다(직전 실행이 `-StableSec` 넘게 돌았으면 `-BaseDelaySec`, 아니면 직전 K의 두 배, 최대 `-MaxDelaySec`). 5의 자손 기다리기 뒤 K초 기다렸다 다시 켠다.
5. 자손 기다리기: 모아 둔 PID 가운데 아직 살아 있고 이름·생성 시각이 모아 둘 때와 같은 것(PID 재사용 가드)이 없어질 때까지 1초마다 본다. `-ChildWaitSec`이 넘으면 그 PID들만 `Stop-Process -Force`로 끄고 끈 PID를 적는다. 이름으로 프로세스를 끄지 않는다(CLAUDE.md — 같은 PC의 다른 python.exe를 건드리면 안 됨).
6. 텔레그램은 이 스크립트가 보내지 않는다. 크래시 때는 옛 Watchdog의 「UI 비정상 종료 감지」, 다시 켜지면 새 Watchdog의 기동 알림이 지금처럼 나간다.
7. 사람이 검은 콘솔 창을 닫으면 그 안의 프로세스가 모두 꺼지고 다시 켜지지 않는다(지금과 같음). 바로가기는 지금처럼 최소화로 띄운다.

**로그인 자동 실행(설정창)**

1. 설정창 「알림설정」 탭의 「자동 재시작」 묶음 맨 위에 체크박스 「PC 로그인 때 자동 실행」과 도움말 「끄기: 여기서 체크 해제, 프로그램이 안 켜지면 작업 관리자 → 시작 앱」을 둔다.
2. 설정창을 열 때 체크 상태는 바로가기 `KBS Monitoring v2.lnk`가 시작프로그램 폴더에 있고 그 대상이 이 저장소의 `실행.bat`과 같을 때만 체크다. 다른 폴더의 `실행.bat`을 가리키면 체크 해제로 보인다(체크하면 이 폴더로 다시 만든다).
3. 체크하면 바로 바로가기를 만든다(대상 `실행.bat`, 작업 폴더 저장소, 창 최소화 7, 설명 「KBS Monitoring v2 자동 실행」 — 지금 등록 bat과 같은 이름·값이라 이미 bat으로 등록한 PC도 체크로 보인다). 해제하면 바로 지운다. `kbs_config.json`에는 아무것도 쓰지 않는다.
4. 바로가기를 만들거나 읽는 일은 새 `utils/autostart.py`가 맡는다. 시작프로그램 폴더 경로를 인자로 받아(기본 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`) 시험이 진짜 폴더를 건드리지 않게 한다. 바로가기는 지금 bat처럼 PowerShell의 `WScript.Shell` COM으로 만들고 읽는다(콘솔 창이 깜빡이지 않게 `CREATE_NO_WINDOW`).
5. 실패하면(권한·PowerShell 실패) 체크박스를 실제 상태로 되돌리고 경고 창에 이유를 보인다. 설정창 로그(`self._logger`가 있으면)에도 남긴다.

**창 자리**

1. 새 `ui/window_state.py`가 `data/window_state.json`을 읽고 쓴다. 내용은 `{"geometry": "<saveGeometry 값의 base64>", "saved_at": "<ISO 시각>"}`. 쓰기는 임시 파일에 쓴 뒤 `os.replace`로 바꿔 크래시 때 반쯤 쓴 파일이 남지 않게 한다.
2. `MainWindow.__init__`이 `resize(1600, 900)` 뒤에 그 파일을 읽어 `restoreGeometry()`한다. 파일이 없거나 깨졌거나 복원이 실패하면 1600×900 그대로 둔다(오류 창 없음, UI 로그에 한 줄).
3. `moveEvent`·`resizeEvent`가 올 때마다 2초짜리 한 번 타이머를 다시 건다. 타이머가 끝나면, 그리고 `closeEvent`에서, 전체화면이 아닐 때만 `saveGeometry()`를 저장한다. 최소화 상태여도 `saveGeometry()`는 보통 창 자리를 담으므로 그대로 저장한다.
4. 전체화면 되살리기는 지금처럼 `ui_state.fullscreen`이 맡는다. 먼저 보통 창 자리를 되살리고 200ms 뒤 전체화면으로 가므로, 전체화면을 풀면 기억한 자리로 돌아온다.
5. 처음 켜는 PC는 지금처럼 1600×900. 감시PC는 처음 켤 때 Win_Tweaks가 잡아 둔 오른쪽 2/3 자리가 그대로 저장된다.

**감시PC 마무리(DESKTOP-HSTUOHH에서만, KBS 쪽 기계 확인이 끝난 뒤)**

1. 감시PC의 지금 KBS를 X로 닫고, 그 검은 콘솔 창까지 닫는다. 새 `실행.bat`으로 켠다(옛 cmd.exe는 옛 `:loop`를 계속 읽으므로 반드시 새로 켠다 — CLAUDE.md 「신규 빌드 배포 시 함정」).
2. 설정창에서 「PC 로그인 때 자동 실행」을 체크한다.
3. `programs.json`의 KBS 항목을 `"kind": "watch"`로 바꾸고 `start`·`placeWindow`·`place`를 지운다. `alive` 세 줄은 그대로 둔다. `"hint": "KBS 실행.bat 콘솔(run_loop.ps1)과 시작프로그램 바로가기 확인"`을 넣는다.
4. `enable.ps1`의 79줄부터 80줄까지를 바꾼다: 바로가기가 없으면 「KBS 시작프로그램 바로가기 없음 — KBS 설정창 알림설정의 『PC 로그인 때 자동 실행』을 켤 것」을 찍는다. 있으면 아무것도 안 찍는다.
5. 그 PC의 `README.md`에서 KBS를 감시 작업이 켠다는 줄(30줄)과 바로가기를 지우라는 줄(42줄)을 「KBS는 스스로 켜지고 다시 켜진다, 감시 작업은 살아 있는지만 본다」로 맞춘다.
6. 이 저장소에서 이 동작이 사용자 판단을 기다리는 자리는 없다. mw-build로 무인 실행하면 1과 2(살아 있는 운영 프로그램을 끄고 켬)는 하지 않고 「막힘: 사용자 판정 필요 — 운영 KBS 재시작」으로 남긴다. 3부터 5까지는 파일 수정이라 무인으로 해도 되지만, 1과 2보다 먼저 하면 그 사이 로그인 때 KBS가 안 켜지므로 1과 2가 끝난 뒤에 한다.
