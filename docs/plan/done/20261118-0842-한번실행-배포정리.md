## 1. 지금 상태

- 새 PC 설치는 파일 셋을 사람이 순서대로 눌러야 한다: `python313_전환.bat`(venv와 패키지) → `install_ffmpeg.bat` → `실행.bat`. 순서는 `★ KBS Monitoring v2 설치 안내.txt` 1~3절, `README.md:171`부터 `README.md:186`까지, `manual/사용안내.html:356`부터 `manual/사용안내.html:367`까지에 적혀 있다.
- `실행.bat`은 `.venv313`이 없으면 NOTICE만 찍고 `py`로 폴백한다(`실행.bat`의 `if exist "%~dp0.venv313\Scripts\python.exe"` 블록). 설치는 하지 않는다. 파일은 ASCII 전용이다(주석에 이유: 일부 PC에서 chcp 65001 아래 한글 REM이 명령으로 오파싱).
- `python313_전환.ps1`은 3.13 확인/설치(16~37줄) → 기존 `.venv313` 삭제 후 생성(41~54줄) → `pip install -r requirements.txt`(58~71줄) 순서이고, 성공·실패 모두 `Read-Host`로 멈춘다(25·33·51·66·84줄). 인수(자동 모드)는 없다. 설치 기록(도장) 파일도 만들지 않는다.
- install.ps1(이 작업에서 지움)은 3.13 고정 없이 `py`(시스템 기본)에 패키지를 설치하고 끝에 `py main.py`로 실행하라고 안내했다(지우기 전 15·43·72줄). `main.py:35`의 필수 패키지 안내도 `install.bat 또는 install.ps1`을 가리킨다.
- 2026-11-18 새 PC 실측(`logs/20261118_ui.txt`): 시스템 파이썬 3.13.15에 psutil·GPUtil·pycaw·requests가 없어 `HEALTH ONSET (UI)`가 찍히고 data 폴더에 ui_degraded.flag가 생겼다. Watchdog이 이를 「UI 프로세스 손상 감지」로 통보했다(`logs/20261118_watchdog.txt`). 원인은 `main.py:465`의 `import psutil` 실패가 `rss_mb == -1`로 이어지고, `main.py:481`의 `degraded_now` 판정이 모듈 없음과 진짜 손상을 구분하지 않는 것이다.
- 기동 자가점검(`processes/watchdog_process.py:107` `_startup_self_check`)은 Python 버전·설정 파일·감지영역·ffmpeg·디스크만 본다. 패키지 누락 항목은 없다(검색: `find_spec`, `부품` 낱말 — 해당 파일에 없음).
- 설정 불러오기(`ui/settings_dialog.py:2461` `_import_config`)는 저장·적용 후 상태 글자만 보여 준다. 재시작 안내는 없다. Watchdog은 설정을 기동 때 1회만 읽어서, 복원 후 재시작해야 `[SYSTEM]` 텔레그램이 나간다(`CLAUDE.md` 「신규 빌드 배포 시 함정」).
- 재시작 길은 이미 있다: `main.py:312` `_restart_requested`, `main.py:313` `RESTART_EXIT_CODE = 42`, `main.py:398`에서 켜고 `window.close()`, `main.py:556`에서 42 반환 → `실행.bat`의 `:loop`가 다시 켠다. 설정창은 `ui/main_window.py:621`에서 만들어지고, `config_saved`만 `ui/main_window.py:628`에서 연결된다. `MainWindow.closeEvent`(`ui/main_window.py:840`)는 `self._cfg`를 저장하는데, 불러오기 직후 `config_saved`가 `_on_config_saved`(`ui/main_window.py:664`)로 `self._cfg`를 새 설정으로 바꾸므로 닫을 때 덮어쓰지 않는다.
- 커밋 검사(`.claude/commit-gate.json`)는 `python -m pytest`(시스템 파이썬)로 돈다. 이 PC의 시스템 파이썬은 3.13.15에 pytest 9.1.1이 있다(실측).
- 자동 시작(`자동시작 등록.bat`, cp949)은 `실행.bat` 바로가기를 시작프로그램에 만든다. 그래서 `실행.bat`이 자가 설치하면 자동 시작도 그대로 따라간다.

## 2. 원하는 동작

**새 총국 PC (처음)**
1. 담당자가 저장소를 받아(clone 또는 ZIP) `실행.bat`을 더블클릭한다.
2. 콘솔에 `[launcher] setup: .venv313 missing - running first-time setup (5-10 min)` 같은 ASCII 안내가 뜨고, `python313_전환.ps1 -Auto`가 돈다: 3.13이 없으면 winget 설치 → `.venv313` 생성 → `pip install -r requirements.txt` → 성공하면 `requirements.txt`를 `.venv313\requirements.installed.txt`로 복사 → ffmpeg가 없으면 winget을 작은 창으로 따로 띄우고 기다리지 않는다(구현 중 정함 — 아래 검사 기록). 자동 모드에서는 `Read-Host`로 멈추지 않는다.
3. `실행.bat`은 PATH 끝에 `%LOCALAPPDATA%\Microsoft\WinGet\Links`를 더한 뒤 `.venv313` 파이썬으로 `main.py`를 켠다.
4. 화면이 뜨면 기동 점검은 `✓ Python 3.13.x · ✗ 설정 파일 없음 · ✓ ffmpeg · ✓ 부품` 모양이 된다(설정은 아직이므로 정상).
5. 설정 > 저장/불러오기 > 불러오기 성공 → 안내창 「설정을 불러왔습니다. 텔레그램 시스템 알림을 켜려면 프로그램을 다시 켜야 합니다. 지금 다시 켤까요? (실행.bat으로 켠 경우 자동으로 다시 켜집니다)」 [지금 다시 켜기] [나중에].
6. [지금 다시 켜기] → 메인 창이 닫히고 종료코드 42 → `실행.bat`이 2초 뒤 다시 켠다 → Watchdog이 새 설정을 읽어 기동 텔레그램이 나간다. [나중에] → 아무 일도 없다(지금 동작 그대로).

**이미 설치된 PC (평소)**
- `.venv313`이 있고 `requirements.txt`가 도장 파일과 같으면 설치 단계 없이 바로 켠다(지금과 같은 속도).
- 업데이트로 `requirements.txt`가 바뀌었으면 `-Auto`가 기존 venv를 지우지 않고 `pip install -r`만 다시 돌린 뒤 도장을 새로 쓴다.

**실패했을 때**
- 설치가 실패하면(인터넷 끊김·winget 없음·pip 오류) 콘솔과 `logs\stderr_debug.txt`에 `[launcher] NOTICE: setup failed (rc=N) - continuing with ...`을 남긴다. venv가 있으면 그 venv로, 없으면 지금처럼 `py`로 켠다. 도장은 갱신하지 않아 다음 실행 때 다시 시도한다.
- 부품이 빠진 채 켜지면 기동 점검에 `✗ 부품 누락: psutil, requests`가 뜬다. 이때 「UI 프로세스 손상 감지」는 뜨지 않는다. UI 로그에는 HEALTH 줄의 `psutil_err=ModuleNotFoundError(...)`만 남고 onset 덤프·`ui_degraded.flag`는 생기지 않는다.
- `실행.bat` 없이 `py main.py`로 켠 경우 [지금 다시 켜기]는 종료만 된다. 안내창 문구가 이를 미리 알린다.

**확인 못 한 것**: Python 3.13이 없는 PC에서 winget이 관리자 승인 창(UAC)을 띄우는지는 이 PC에 3.13이 이미 있어 확인 못 했다. 창이 뜨면 담당자가 「예」를 누르면 되고, 거절하면 위 「실패했을 때」 경로로 간다.

**사람 판단**: 없음 — 무인 구현 중 사용자 판정이 필요한 단계는 없다. 다만 4칸의 「눈」 행은 사람이 확인한다.

## 5. 하지 않는 것

- 오프라인 설치판(파이썬·부품 동봉) — 총국 PC가 인터넷이 된다(사용자 확인). 막힌 총국이 나오면 그때 별도 계획.
- `PYTHONMALLOC=debug` 끄기 — 발표 뒤에 정하기로 함. 인계 파일로 남긴다.
- Detection 쪽 `DIAG 오류`(`processes/detection_process.py:1255` `import psutil`) 처리 — 부품이 설치되면 사라지고, 이번 요구(설치 자동화)와 무관.
- 심사위원 소개서(`docs/소개서/`) 수정 — 남긴 파일 이름 그대로라 어긋나지 않는다.
- Watchdog이 설정을 다시 읽게 하는 구조 변경 — 재시작 버튼으로 충분하다는 사용자 결정.
- `디버그실행.bat` 정리 — 요구 밖.
